# 缺陷记录：RCN12 训练流中联合任务的变体错位（2026-09-23）

**现象**：第一次租机的 RCN12 八臂里，教过的面 fC123 的联合探针在**干预变体上 100% 正确、正常变体上 0%**（解析率 1.0），fB123 同样；于是 `min(替换, 不替换)` 定义的面分数恒为 0，θ=0.8 下 β₁ 在 224 步后停在 3、没有任何 clean_fill。

**根因**：`spec_world.build()` 调用 `joint_task(fname, idx, other, t, rid, override, split)` 时把第 5、6 个实参写成了 `(bool(j % 2), f'tr_j_{s}_{j}')`，即 `rid` 得到布尔值、`override` 得到非空字符串（恒为真）。因此训练流中**全部**联合样本都是"将中间状态明确替换为 …"的干预变体，"保持按词典得到的中间状态"的正常变体从未被训练过，模型对该指令只能乱答。探针行由另一处正确调用生成，本身无误。审计未发现，因为它只检查 gold 自洽和课程表，不检查变体平衡与 id 类型。

**影响**：RCN12（601–604）的面测量无效；边、顶点、安慰剂、潜在胞腔的结论不受影响（潜在面本来就为 0）。不重跑 RCN12：面的正对照由修正后的 RCN12_FORGET（611/612，768 步）覆盖。

**修复**：`build()` 改为关键字实参；`build()` 与 `audit.py` 新增断言——联合行 `override` 必须是布尔、`id` 必须是字符串、替换/不替换比例在 0.4–0.6、训练 id 唯一。

**顺带修正**：三步链迁移任务此前从未训练过其三字段格式（解析率 0.03–0.16），改为在训练流中加入链格式练习（`train_chains`，每步 4 条，只用教过的边、训练根），迁移链仍用独立根。
